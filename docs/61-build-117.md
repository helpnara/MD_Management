## 녹화에서 본 것 (0.1초씩)

- 노트 목록에서 **돌아올 때** — 찾기 칸이 바탕 없이 글자(*모든 노트에서 찾기*)만 먼저 나오고, 0.3초쯤 뒤 회색 칸이 덧입혀지며 **아래로 튄다**

**까닭** — 시스템 찾기 칸(`.searchable` · `navigationBarDrawer(.always)`)은 화면이 아니라 **내비게이션 막대**가 그린다. 화면을 넘길 때 막대가 칸을 따로 숨겼다 보였다 한다.

## 빌드 117 확인 목록 — 사용자 관점 (코드를 읽고 적었다)

0. 설정 → 진단 정보 → **판** 이 `1.1.14 (117)` — 아니면 테스트플라이트에서 업데이트한 뒤 1 부터

**넘어갈 때 (녹화와 같은 동작)**

1. 폴더 화면 맨 위에 **회색 둥근 찾기 칸** (돋보기 · *모든 노트에서 찾기*)이 있다
2. 폴더 하나를 눌러 들어간다 → 칸이 화면과 **함께** 밀려 나가고, 칸 글자가 노트 목록 위에 **남지 않는다**
3. 뒤로 → 칸이 화면과 함께 들어오고, **글자만 먼저 나오거나 아래로 튀지 않는다** (어두운 화면에서도)

**칸이 하는 일 (빌드 115 · 116 과 같아야 한다)**

4. 칸을 누른다 → 글쇠판 · **최근 고친 노트** · 칸 오른쪽에 **취소** → 취소 → 폴더 목록 · 글쇠판이 내려간다
5. 낱말을 친다 → 결과 · 칸 안 오른쪽 **ⓧ** 를 누르면 글이 지워지고 최근 고친 노트로 돌아온다
6. 결과나 최근 고친 노트를 누른다 → 글쇠판이 내려가며 **한 번에** 노트로 넘어가고, *노트를 열 때 읽기 모드로* 설정대로 열린다 (링크가 된다)
7. 폴더가 많으면 목록을 위로 민다 → 칸도 함께 올라간다 (목록의 첫 줄이다) → 맨 위로 되돌리면 다시 보인다
8. 노트 목록 화면에서 아래로 당겨 나오는 찾기 칸은 **예전 그대로**다

**아이패드** (있으면)

9. 왼쪽 폴더 칸 맨 위에 같은 칸 · (외부 키보드) `⌘F` → 왼쪽 칸이 보이며 찾기 칸에 글쇠가 간다
