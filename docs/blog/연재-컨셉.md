## 추천 — 연재 3편

| 편 | 제목 예 | 뼈대 |
|---|---|---|
| **1편** | *맥도 없이, 2주 만에 앱스토어에 앱을 냈다* | ① + 숫자 표. 왜 이 앱이 필요했나 — **글이 앱 안에 갇히지 않고 내 파일로 남게** |
| **2편** | *버그는 내 하루가 찾았다* | ② 장면 서너 개 + 사진. 불편 → 번호 → 빌드 → 확인 |
| **3편** | *AI는 잊어도 문서는 기억한다* | ③ 규칙들 + **AI가 틀린 순간들** |

### 3편에 꼭 넣을 것 — AI가 틀린 장면 (글을 믿을 만하게 만든다)

- 키보드를 내리고 캡처하라고 했는데, 내리면 원문 표시가 사라지게 **우리가 만들어 놨었다** (161)
- 스토어 스크린샷 크기를 짐작으로 맞췄다가 **한 바퀴를 버렸다** (6.9인치 → 실제 칸은 6.5인치)
- 폴더 이름 바꾸기를 새로 만들려고 보니 **이미 있었다** — 문제는 기능이 아니라 *찾을 수 없음* 이었다 (167)
- 스토어 설명에 `>>` 를 적어 두었는데, 줄 맨 앞에서는 안 되는 방아쇠였다 — **심사자가 헷갈릴 자리를 미리 뺐다** (160)

- 한글을 치다가 **같은 자리에서 여섯 번** — 짐작으로 다섯 번 고치고, 여섯 번째에 기록을 받아 풀었다 (190 · 2편 초안에서 넘겨 왔다 — `2편-네이버.md` 맨 아래)
- 애플 개발자 콘솔의 Description 칸에 **한글 이름을 적으라고 안내**했다 — 콘솔은 한글을 안 받는다 (213 · 사용자가 영문으로 고쳐 넣고 *문서에도 반영해줘*)
- 스크롤 막대를 **둘** 만들었다 — iOS 기본 막대와 앱 막대. 사용자 — *꼭 2개 이렇게 구현해야 하는 거야?* → 하나로 (202)

### 마무리 장면

첫 심사에서 받은 **정보 요청** 메일. 반려인 줄 알았는데 *처음 앱을 내는 계정이라 더 알고 싶다* 는
뜻이었다. 홈 화면에서 앱을 켜는 장면부터 녹화해 보냈다 — 그리고 결과를 기다리며 이 글을 쓴다.
**심사가 통과하면 그 소식이 1편의 끝이다.**

## 조심할 것

- **스크린샷은 스토어용(견본 노트)만 쓴다.** 실제 노트에는 회사 이름 · 일정 같은 개인 정보가 있었다 (`docs/11-store-screenshots.md` §0)
- 저장소가 공개라 링크해도 되지만 **지원 메일 · 개인 연락처는 빼고** 쓴다
- *코딩을 몰라도* 라고 쓴다면, 대신 **사람이 판단한 것**을 보여 준다 — 무엇을 만들지, 언제 빌드할지, 무엇을 빼기로 했는지. 그것이 이 이야기의 주인공이다
- 다른 앱 이름 — 블로그는 스토어가 아니라 규칙(§6)의 테두리 밖이지만, **남의 상표로 우리 앱을 설명하지 않는** 쪽이 앱 소개와 결이 맞다
