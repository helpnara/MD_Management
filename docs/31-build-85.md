## 빌드 85 확인 목록 — 사용자 관점 (코드를 읽고 적었다)

0. 설정 → 진단 정보 → **판** 이 `1.0.8 (85)` — 아니면 테스트플라이트에서 업데이트한 뒤 1 부터

**아이폰**

1. 폴더 화면에서 최상위 폴더 하나(예: `회의`)를 눌러 노트 목록으로 들어간다 → 위 오른쪽, 새 노트 단추 **왼쪽에 폴더+ 단추**가 있다
2. 1 의 폴더+ 단추 → 창에 *회의 안에 폴더를 만듭니다* → 이름 `시험` → **만들기** → `시험` 폴더의 노트 목록으로 바뀌고, 폴더 화면으로 돌아가면 `회의` 바로 아래에 `시험` 이 보인다
3. 2 에서 만든 `시험` 폴더 안(노트 목록)에서 폴더+ 단추 → 창에 *폴더는 두 단계까지라 회의 안에 만듭니다* → 이름 `시험2` → 만들기 → 폴더 화면에서 `회의` 아래에 `시험` 과 **나란히** `시험2` 가 있다 (`시험` 안이 아니다)
4. 폴더 화면(맨 처음 화면) 위의 폴더+ 단추 → 창에 *<맨 위 폴더 이름> 안에 폴더를 만듭니다* → 만든 폴더가 **최상위**에 생긴다 (지금과 같다)

**아이패드 (가로 · 세 칸)**

5. 왼쪽 폴더 칸에서 최상위 폴더(예: `회의`)를 고른 채, 폴더 칸 위의 폴더+ 단추 → 창에 *회의 안에 폴더를 만듭니다* → 만들면 `회의` 아래에 생긴다
6. 폴더 칸에서 2단계 폴더(예: `회의/시험`)를 고른 채 폴더+ 단추 → *폴더는 두 단계까지라 회의 안에 만듭니다*
7. 폴더 칸 맨 위(전체 · 최상위)를 고른 채 폴더+ 단추 → 최상위에 생긴다
8. 가운데 노트 목록 칸 위에도 폴더+ 단추가 있고, 누르면 5~7 과 같은 자리에 만든다

**전과 같은 것**

9. 최상위 폴더를 **길게 누르면** `안에 폴더 만들기` 가 그대로 있고, 그 폴더 안에 만든다

정리: 확인에 만든 `시험` · `시험2` 폴더는 길게 눌러 **지우기**로 치운다 (휴지통으로 간다).

## 결과 (2026-10-07 사용자)

**0~9 확인 완료 — 단 5 ❌.** *5번에서 폴더 선택 후, 폴더 목록에서 폴더 만들기 하면 문구는 하위 폴더가 생기는 것으로 나오는데, 실제로는 최상위 폴더 아래에 폴더가
생기고 있어 … 노트 목록에서 폴더를 만들면 하위 폴더가 생성되고 있어(정상 동작).*

**원인.** 폴더 칸 단추가 *아이폰인가* 를 **폴더 칸 자신의** size class 로 갈랐다 — 아이패드의 폴더 칸은 좁아서 compact 다. 그래서 아이폰 길(`beginCreateFolder()` —
맨 위)을 탔다. 창 문구 *<맨 위 폴더 이름> 안에 폴더를 만듭니다* 는 맨 위를 뜻했지만 **하위 폴더처럼 읽혔다.** 노트 목록 단추는 갈래 없이 `beginCreateFolderHere` 라 맞았다.
**어느 칸에서 잡았어야 했나.** 바깥 화면 폭은 이미 `rootIsCompact` 하나로 재고 있었다 (빌드 24 · 13번 · 125 — 같은 함정을 두 번 겪고 만든 값). 옆에 하나 더 쟀다 —
*같은 것을 재는 곳이 둘이면 갈린다* (CLAUDE.md §1). 아이패드 갈래는 시뮬레이터 스크린샷이 안 누르는 자리라 사람만 잡는다.

**고침.** 폴더 칸 단추는 `rootIsCompact` 로 가른다. 맨 위에 만들 때 창 문구는 **맨 위에 폴더를 만듭니다** — 폴더 이름을 대지 않는다. → 다음 빌드.
