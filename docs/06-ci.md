# CI · TestFlight 절차

## 1. 워크플로 네 개

| 파일 | 언제 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| `core-test.yml` | `Packages/Core/**` · `Tools/golden/**` 푸시 | ① ubuntu: 파이썬 기댓값이 최신인지 ② `swift:6.1-noble` 컨테이너: `swift build` + `swift test` | 2~4분 |
| `build.yml` | `App/**` · `Packages/**` · `project.yml` 푸시 | macOS: XcodeGen → 빌드 → 스크린샷(iPhone · 큰 글씨 · 다크 · iPad) → 아티팩트 → `screenshots/` 커밋 | 10~15분 |
| `testflight.yml` | **수동** — 사용자가 "착수하자" 할 때만 | 아카이브 · 서명 · 검증 · 업로드 | 15~20분 |
| `site.yml` | `docs/privacy.md` 변경 | GitHub Pages 에 방침 한 장 | 1분 |

`docs/**` 와 `**.md` 만 고친 푸시는 `build.yml` 이 건너뛴다 (`paths-ignore`).

## 2. 처음 한 번 — 사용자가 해야 하는 것

### 2.1 저장소 시크릿 4개

**Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 | 어디서 |
|---|---|---|
| `APPLE_TEAM_ID` | 10자 팀 ID | developer.apple.com → Membership |
| `APP_STORE_CONNECT_KEY_ID` | 10자 키 ID | App Store Connect → Users and Access → Integrations → App Store Connect API |
| `APP_STORE_CONNECT_ISSUER_ID` | UUID | 같은 화면 위쪽 |
| `APP_STORE_CONNECT_KEY_P8` | `.p8` 파일 **내용 전체** (`-----BEGIN PRIVATE KEY-----` 줄 포함) | 키를 만들 때 한 번만 받는다 |

> **배포용 인증서 P12 는 쓰지 않는다.** 자동 서명 + 클라우드 서명으로 굽는다.
> 지난 앱(`Asset-management`)과 같은 방식 · 같은 이름이므로, 그 저장소의 시크릿을
> 그대로 복사하면 된다 — 그것이 되는지가 **가정 A9** 다.

### 2.2 API 키 권한은 반드시 **Admin**

App Manager 로는 서명 자산을 못 만든다. `Cloud signing permission error` 가 나면
코드 문제가 아니라 이것이다.

### 2.3 팀에 기기가 최소 하나 등록돼 있어야 한다

자동 서명은 아카이브를 개발용 프로파일로 굽는데, 개발용 프로파일은 기기 없이는
발급되지 않는다. 배포용 서명은 내보내기 단계에서 다시 입혀진다.

### 2.4 App Store Connect 에 앱 등록

- 번들 ID: `com.helpnara.markdown` — **등록 후 못 바꾼다**
- 이름: 미정 (A1 — `docs/roadmap.md` §4)
- 개인정보 처리방침 URL: `https://helpnara.github.io/MD_Management/privacy/`

### 2.5 GitHub Pages

**Settings → Pages → Source 를 `GitHub Actions` 로.**

## 3. 막다른 길 — 다시 시도하지 말 것

지난 앱에서 확인된 것들이다.

| 시도 | 결과 |
|---|---|
| `CODE_SIGN_IDENTITY` 를 배포용으로 강제 | 자동 서명과 충돌로 거부 |
| `CODE_SIGNING_ALLOWED=NO` 로 아카이브 | `ProcessProductPackaging` 이 건너뛰어져 **entitlements 가 앱에 안 박힌다** (iCloud 가 통째로 빠진다) |
| `CODE_SIGN_IDENTITY=-` (애드혹) | SDK 가 거부 |
| `manageAppVersionAndBuildNumber` 를 안 끔 | Xcode 가 빌드 번호를 제멋대로 바꾼다 — 대화에서 부르는 번호와 폰의 번호가 달라진다 |

## 4. 자주 나는 오류

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `maximum number of certificates` | 러너가 매번 새 기계라 개발 인증서를 계속 발급 | developer.apple.com → Certificates 에서 오래된 **Apple Development** 폐기. **배포용은 건드리지 않는다** |
| `no devices from which to generate a provisioning profile` | 팀에 기기가 없다 | 기기 하나 등록 (§2.3) |
| `Cloud signing permission error` | API 키 액세스가 Admin 이 아니다 | §2.2 |
| `iOS 26.0 is not installed` | Xcode 를 다른 26.x 로 바꿨다 | 이미 26 이상이면 손대지 않는다 (워크플로가 그렇게 돼 있다) |
| 워크플로가 커밋을 못 함 (403) | 기본 토큰이 읽기 전용 | `permissions: contents: write` |
| 푸시 거부 (non-fast-forward) | CI 가 스크린샷을 커밋함 | 푸시 전 `git pull --rebase` |
| `The Xcode build system has crashed` 가 **같은 자리에서 두 번** | 소스 문자열 안의 곧은 따옴표 | 안내 문구 강조는 `**…**` 로. 두 번 같은 자리면 러너 탓이 아니다 |
| `pip3 install` 이 PEP 668 로 거부 | 시스템 파이썬 보호 | `python3 -m venv` 뒤 설치 (워크플로가 그렇게 돼 있다) |

## 5. 원격 세션에서 미리 돌려 볼 수 있는 것

```bash
python3 -m venv .venv
.venv/bin/pip install -r Tools/golden/requirements.txt

.venv/bin/python Tools/golden/generate.py          # 기댓값 다시 만들기
.venv/bin/python Tools/golden/generate.py --check  # CI 와 같은 검사
python3 Tools/site/build.py /tmp/_site             # 방침 페이지 미리 보기
```

**`swift` 는 여기 없다.** 설치하려 하지 마라 — `download.swift.org` 가 네트워크
정책으로 막혀 있다 (`CLAUDE.md` §2).
