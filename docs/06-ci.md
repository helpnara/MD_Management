# CI · TestFlight 절차

## 1. 워크플로 네 개

| 파일 | 언제 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| `core-test.yml` | `Packages/Core/**` · `Tools/golden/**` 푸시 | ① ubuntu: 파이썬 기댓값이 최신인지 ② `swift:6.1-noble` 컨테이너: `swift build` + `swift test` | 2~4분 |
| `build.yml` | `App/**` · `Packages/**` · `project.yml` 푸시 | macOS: XcodeGen → 빌드 → 스크린샷(iPhone · 큰 글씨 · 다크 · iPad) → 아티팩트 → `screenshots/` 커밋 | 10~15분 |
| `testflight.yml` | **수동** — 사용자가 "착수하자" 할 때만 | 아카이브 · 서명 · 검증 · 업로드 | 15~20분 |
| `site.yml` | `docs/privacy.md` 변경 | GitHub Pages 에 방침 한 장 | 1분 |

`docs/**` 와 `**.md` 만 고친 푸시는 `build.yml` 이 건너뛴다 (`paths-ignore`).

## 2. 처음 한 번 — 사용자가 해야 하는 것

### 2.0 ⚠️ 시크릿은 옛 저장소에서 복사할 수 없다

GitHub 시크릿은 **쓰기 전용**이라 `Asset-management` 에서 값을 꺼내볼 수 없다.
넷 중 셋은 다시 찾아보면 되지만 **`.p8` 파일은 만들 때 딱 한 번만 받는다.**

| 값 | 다시 구할 수 있나 |
|---|---|
| `APPLE_TEAM_ID` | ✅ 포털에 보임 |
| `APP_STORE_CONNECT_ISSUER_ID` | ✅ ASC 화면 위쪽 |
| `APP_STORE_CONNECT_KEY_ID` | ✅ 키 목록 |
| `APP_STORE_CONNECT_KEY_P8` | ❌ 보관해 뒀어야 한다. 없으면 §2.5 에서 **새 키를 만든다** (옛 키를 지우지 않으면 지난 앱은 계속 돈다) |

### 2.1 순서 — 2.2 와 2.3 을 바꾸면 첫 빌드가 서명에서 막힌다

```
iCloud 컨테이너 → App ID(+컨테이너 연결) → 기기 확인 → ASC 앱 등록 → API 키 → 팀 ID → 시크릿 4개
```

### 2.2 iCloud 컨테이너를 **먼저** 만든다

<https://developer.apple.com/account/resources/identifiers/list/cloudContainer>
→ **+** → **iCloud Containers**

| 항목 | 값 |
|---|---|
| Description | `Markdown` |
| Identifier | `iCloud.com.helpnara.markdown` |

**App ID 보다 먼저 만드는 이유:** App ID 를 만드는 화면에서는 컨테이너를 고를 수
없다. 등록을 마치고 편집 화면으로 다시 들어가야 고를 수 있는데, 그때 고를 것이
없으면 또 나갔다 와야 한다.

> 이 식별자는 `project.yml` 과 `App/Notebook.entitlements` 두 곳에 박혀 있다.
> **한 글자만 틀려도 앱은 빌드되는데 `Files` 앱에 폴더가 안 보인다.**

### 2.3 App ID 를 만들고 컨테이너를 연결한다

<https://developer.apple.com/account/resources/identifiers/list> → **+** → **App IDs** → **App**

| 항목 | 값 |
|---|---|
| Description | `Markdown` |
| Bundle ID | **Explicit** 로 `com.helpnara.markdown` |

- **반드시 `Explicit`.** `Wildcard` 로는 iCloud 를 못 쓴다.
- Capabilities 는 **☑ iCloud 하나만.** 지난 앱과 달리 **Push Notifications 는
  체크하지 않는다** — 이 앱은 알림을 안 쓴다.

**등록을 마친 뒤** 목록에서 다시 열어 **iCloud → Configure** → 2.2 의 컨테이너 체크
→ Continue → **Save**. 편집 화면의 iCloud 줄에 컨테이너가 보이면 된 것이다.

### 2.4 기기가 하나라도 등록돼 있는지

<https://developer.apple.com/account/resources/devices/list> — **비어 있으면 안 된다.**
자동 서명이 아카이브를 개발용 프로파일로 굽는데, 개발용 프로파일은 기기 없이는
발급되지 않는다.

### 2.5 App Store Connect 에 앱 등록

<https://appstoreconnect.apple.com> → **앱** → **+** → **신규 앱**

| 항목 | 값 |
|---|---|
| 플랫폼 | iOS |
| 이름 | 후보 하나 (A1 미확정 — **첫 심사 제출 전까지 언제든 바꿀 수 있다**) |
| 기본 언어 | 한국어 |
| 번들 ID | `com.helpnara.markdown` |
| SKU | `markdown` |

이미 쓰이는 이름이면 거부된다 — 그 자체가 이름 후보 검증이 된다.

### 2.6 API 키 — **앱마다 만드는 것이 아니다**

App Store Connect API 키는 **팀(계정) 단위**다. 키 하나가 그 팀의 **모든 앱**을
다룬다. 그래서 네 값은 지난 앱과 **완전히 같은 값을 그대로** 쓴다 — 새 앱을
만들 때마다 바꾸는 것이 아니다.

| 값 | 범위 |
|---|---|
| `APPLE_TEAM_ID` | 팀 전체 |
| `APP_STORE_CONNECT_ISSUER_ID` | 팀 전체 |
| `APP_STORE_CONNECT_KEY_ID` | 키 하나 — 팀의 모든 앱에 통한다 |
| `APP_STORE_CONNECT_KEY_P8` | 같은 키의 비밀 파일 |

**새로 만들어야 하는 경우는 셋뿐이다:**

1. `.p8` 파일을 잃어버렸다 (다시 못 받는다)
2. 그 키를 `App Manager` 로 만들었다 — 권한은 나중에 못 바꾼다 (§2.9)
3. 키를 해지(Revoke) 했다

**`.p8` 이 있으면 이 절은 건너뛴다.** 아래는 새로 만들 때만.

<https://appstoreconnect.apple.com/access/integrations/api> → **팀 키** → **+**
이름 `GitHub Actions`, 액세스 **Admin** (§2.2 아래의 경고 참고).
`AuthKey_XXXXXXXXXX.p8` 을 **딱 한 번** 받는다. 키 ID 와 발급자 ID 를 적어 둔다.

### 2.7 팀 ID

<https://developer.apple.com/account> → **Membership details** → `Team ID`

### 2.8 저장소 시크릿 4개

<https://github.com/helpnara/MD_Management/settings/secrets/actions> → **New repository secret** 을 네 번. **이름 철자가 정확해야 한다.**

| 이름 | 값 | 어디서 |
|---|---|---|
| `APPLE_TEAM_ID` | 10자 팀 ID | developer.apple.com → Membership |
| `APP_STORE_CONNECT_KEY_ID` | 10자 키 ID | App Store Connect → Users and Access → Integrations → App Store Connect API |
| `APP_STORE_CONNECT_ISSUER_ID` | UUID | 같은 화면 위쪽 |
| `APP_STORE_CONNECT_KEY_P8` | `.p8` 파일 **내용 전체** (`-----BEGIN PRIVATE KEY-----` 줄 포함) | 키를 만들 때 한 번만 받는다 |

> `.p8` 은 **줄바꿈까지 그대로** 넣는다. 한 줄로 붙으면 서명이 실패한다.
>
> **배포용 인증서 P12 는 쓰지 않는다.** 자동 서명 + 클라우드 서명으로 굽는다.
> 지난 앱(`Asset-management`)과 **같은 방식 · 같은 이름**이므로 같은 키를 그대로
> 쓸 수 있다 — 그것이 되는지가 **가정 A9** 다. 다만 §2.0 대로 **값을 그 저장소에서
> 꺼내올 수는 없다.** 원본 `.p8` 파일이 필요하다.

### 2.9 API 키 권한은 반드시 **Admin**

App Manager 로는 서명 자산을 못 만든다. `Cloud signing permission error` 가 나면
코드 문제가 아니라 이것이다.

### 2.10 왜 기기가 필요한가

자동 서명은 아카이브를 개발용 프로파일로 굽는데, 개발용 프로파일은 기기 없이는
발급되지 않는다. 배포용 서명은 내보내기 단계에서 다시 입혀진다.

### 2.11 참고 — 값이 박혀 있는 곳

- 번들 ID: `com.helpnara.markdown` — **등록 후 못 바꾼다**
- 이름: 미정 (A1 — `docs/roadmap.md` §4)
- 개인정보 처리방침 URL: `https://helpnara.github.io/MD_Management/privacy/`

**Settings → Pages → Source 를 `GitHub Actions` 로.**

## 4. 자주 나는 오류

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `maximum number of certificates` | 러너가 매번 새 기계라 개발 인증서를 계속 발급 | developer.apple.com → Certificates 에서 오래된 **Apple Development** 폐기. **배포용은 건드리지 않는다** |
| `no devices from which to generate a provisioning profile` | 팀에 기기가 없다 | 기기 하나 등록 (§2.3) |
| `Cloud signing permission error` | API 키 액세스가 Admin 이 아니다 | §2.2 |
| `iOS 26.0 is not installed` | Xcode 를 다른 26.x 로 바꿨다 | 이미 26 이상이면 손대지 않는다 (워크플로가 그렇게 돼 있다) |
| 워크플로가 커밋을 못 함 (403) | 기본 토큰이 읽기 전용 | `permissions: contents: write` |
| 푸시 거부 (non-fast-forward) | CI 가 스크린샷을 커밋함 | 푸시 전 `git pull --rebase` |
| `The Xcode build system has crashed` 가 **같은 자리에서 두 번** | 소스 문자열 안의 곧은 따옴표 | 안내 문구 강조는 `**…**` 로. 두 번 같은 자리면 러너 탓이 아니다 |
| `pip3 install` 이 PEP 668 로 거부 | 시스템 파이썬 보호 | `python3 -m venv` 뒤 설치 (워크플로가 그렇게 돼 있다) |

## 5. 원격 세션에서 미리 돌려 볼 수 있는 것

```bash
python3 -m venv .venv
.venv/bin/pip install -r Tools/golden/requirements.txt

.venv/bin/python Tools/golden/generate.py          # 기댓값 다시 만들기
.venv/bin/python Tools/golden/generate.py --check  # CI 와 같은 검사
python3 Tools/site/build.py /tmp/_site             # 방침 페이지 미리 보기
```

**`swift` 는 여기 없다.** 설치하려 하지 마라 — `download.swift.org` 가 네트워크
정책으로 막혀 있다 (`CLAUDE.md` §2).
