## 빌드 78 확인 목록 — 사용자 관점 (코드를 읽고 적었다)

**읽기 화면에서 체크상자 누르기 (211)**

1. 쓰기 화면에 `- [ ] 우유 사기` 와 `- [x] 빵 사기` 두 줄을 쓰고 읽기 모드로 → **체크상자를 누르면** 켜지고, 다시 누르면 꺼진다. 켜진 것도 눌러 끌 수 있다
2. 1 에서 누른 뒤 쓰기 모드로 → 누른 줄만 `- [x] 우유 사기` 처럼 바뀌어 있고 다른 줄은 그대로다
3. 체크상자가 화면 아래쪽에 있을 만큼 **긴 노트**에서 아래쪽 체크상자를 누른다 → 화면이 맨 위로 튀지 않고 그 자리에 머문다 (한 번 깜빡일 수 있다)
4. `1. [ ] 번호 할 일` · `> - [ ] 인용 속 할 일` · 들여쓴 `  - [ ] 안쪽 할 일` 도 읽기 모드에서 눌러 켜진다
5. 체크상자 **옆의 글**을 누르면 아무 일도 없다 (글 고르기 · 찾기는 전처럼)

**쓰기 화면 코드 상자 (210)**

6. 쓰기 화면에서 ```` ``` ```` 줄 · 코드 두세 줄 · ```` ``` ```` 줄을 쓴다 → **여는 줄부터 닫는 줄까지** 화면 폭 전체에 회색 상자가 깔리고, 줄 사이에 흰 틈이 없다
7. 상자 안의 글을 길게 눌러 고른다 → 고른 표시(파란 바탕)가 보인다
8. 다크 모드로 바꾼다 → 상자가 검은 바탕보다 조금 밝은 회색이다
9. 닫는 ```` ``` ```` 를 지우면 그 아래 줄들도 상자 안으로 들어가고, 다시 치면 돌아온다 (닫는 줄 밑에 글 한 줄을 두고 보면 잘 보인다)
10. 네 칸 들여쓴 줄(목록 아래 겹친 글 등)에는 상자가 **안** 깔린다

11. 설정 → 진단 정보 → **판** 이 `1.0.6 (78)`

**참고 (번호 없이):** 체크상자를 누른 노트를 껐다 켜도 그대로인가 · 다른 앱에서 열어도 `[x]` 로 같은가.

## 결과 (2026-10-03 사용자 — 화면 두 장)

**1~5 확인 완료.** 4 는 사용자가 화면으로 다시 보자고 했다:

| 줄 | 읽기 화면 | 판정 |
|---|---|---|
| `1. [x] 번호 할 일` | 체크상자 · 눌러 켜짐 | ✅ |
| `> - [ ] 인용 속 할 일` | **점 + 글자 `[ ]`** — 체크상자가 아니다 | ❌ → 고침 (아래) |
| `  - [ ] 안쪽 할 일` (인용 바로 밑) | 맨 앞 단계의 체크상자 | ✅ 표준대로 — 인용 밑 줄은 `>` 가 없어 인용 밖의 **새 목록**이고, 위에 인용 밖 항목이 없어 겹칠 곳이 없다 |

**인용 안의 체크상자.** 앱의 읽기 화면을 그리는 cmark-gfm 이 인용 안의 체크상자를 글자로 남긴다 (파이썬 cmark-gfm 으로도 똑같이 나온다).
GFM 규격은 인용 안의 목록 항목을 막지 않고, markdown-it 의 체크상자 확장은 체크상자로 읽는다 → 렌더러의 한계다.
**어느 칸에서 잡았어야 했나:** 정답표(`taskLines`)에 인용 사례가 없었고, 심판이 cmark-gfm 하나라 그 한계를 정답으로 삼았다.
**고친 것:** `MarkdownHTML.linkTasks` 가 글자 `[ ]` · `[x]` 로 시작하는 목록 항목을, **원문 줄이 체크상자 줄일 때만**(`TaskToggle.marker` — 뒤집을 때와 같은 잣대)
체크상자로 그리고 링크를 씌운다. `\[ ]` 로 막은 줄은 그대로. 정답표에 인용 · 두 겹 인용 · 인용 안 번호 · 겹침 · 느슨한 목록 · 막은 줄을 더하고,
인용이 든 사례는 markdown-it 의 체크상자 확장(`mdit-py-plugins`)이 심판이다 (인용이 없으면 앱과 같은 cmark-gfm).
