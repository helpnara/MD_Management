# ADR-0001 — 파일이 원본이다

**상태** 확정 (2026-09-13)

## 맥락

지난 앱(`느린 부자의 기록`)에서 가장 비싼 실수는 **저장 계층을 요구사항 끝까지 보지
않고 고른 것**이었다. SwiftData 로 시작했다가 "다른 Apple ID 와 가족 공유" 앞에서
`CKShare` 를 지원하지 않는다는 것을 알고 Core Data 로 옮겼고, 12개 모델을 옮기는 데
한 차수의 절반이 들었다 (`자산관리_앱-LESSONS_LEARNED.md` §0-1).

그래서 이 앱에서는 **"누구와 나눌 것인가" 를 먼저 물었다.** 답은 "아무와도 안
나눈다 — 내 기기들끼리만" 이다. iCloud Drive 가 기기 사이 동기화를 이미 한다.

## 결정

**사용자 폴더의 `.md` 파일과 이미지가 유일한 진실이다. 앱에는 자료 DB 가 없다.**

- 본문을 Core Data · SwiftData · 어떤 저장소에도 복사해 두지 않는다.
- 자체 파일 형식이 없다. 앱을 지워도 자료는 그대로 남는다.
- 유일한 앱 사설 저장소는 **검색 색인**인데, 그것은 자료가 아니라 **언제든 지워도 되는
  캐시**다 (ADR-0003).
- 기기 편의(마지막 연 파일 · 스크롤 위치 · 커서)는 `UserDefaults` 에 두고 iCloud 로
  보내지 않는다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| Core Data / SwiftData 에 본문 복사 | **두 개의 진실**이 생긴다. 파일이 밖에서 바뀌면(다른 기기 · 옵시디언 · Files 앱) 어느 쪽이 맞는지 정하는 코드가 필요하고, 그 코드의 버그가 곧 자료 손실이다 |
| CloudKit 동기화 | 공유 요구가 없다. `NSPersistentCloudKitContainer` 를 안 쓰면 **CloudKit 스키마 · Development→Production 배포 · `.ckdb` 대조 스크립트가 통째로 사라진다** (지난 앱 워크플로 7개 중 2개가 이것 때문에 있었다) |

## 결과

- 좋은 것: 자료 손실 위험이 구조적으로 낮다. 사용자가 옵시디언 · Files 앱과 섞어 써도 된다.
- 대가: 목록 · 검색이 **파일을 읽어야** 만들어진다. 그래서 색인과 `mtime` 감시가 필요하고,
  iCloud 미다운로드 파일(`.icloud` 자리표시)을 다루는 코드가 생긴다.
- **이 결정을 어기는 신호:** 본문 문자열을 앱 저장소에 쓰는 코드가 보이면 되돌린다.
