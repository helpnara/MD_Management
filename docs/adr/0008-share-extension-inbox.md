# ADR-0008 — 공유 확장은 사용자 폴더를 열지 않고 앱 그룹 상자에 맡긴다

**상태** 확정 (2026-10-03 · 213 · 빌드 81 확인 · 1.0.6)

## 맥락

다른 앱의 공유 메뉴에서 **느린 여백에 보내기**(공유 확장)를 만들었다 (2026-10-03 사용자 — *하나씩 구현해 보자*).
확장은 앱과 **다른 프로세스**다. 사용자의 노트 폴더는 (a) 앱의 iCloud 컨테이너이거나 (b) 사용자가 고른 폴더(보안 범위 북마크)다 (ADR-0002).
확장이 그 폴더에 바로 쓰려면 iCloud 자격 · 북마크를 확장과 나눠야 하는데, 기기 · 폴더 종류마다 미덥지 않고 실패하면 **조용히 사라진다**.

## 결정

**확장은 받은 것을 앱 그룹 컨테이너의 상자(`Inbox/<칸>/`)에 두기만 한다. 앱이 앞으로 나올 때 상자를 비워 `받은 글` 폴더의 새 노트로 옮긴다.**

- 앱 그룹: `group.com.helpnara.markdown` — 앱(`com.helpnara.markdown`)과 확장(`com.helpnara.markdown.share`) 둘 다의 자격 · 개발자 콘솔 등록 (`docs/06-ci.md` §2.13).
- 상자 코드는 하나 — `Shared/ShareInbox.swift` (actor), 앱과 확장이 함께 빌드한다.
- 칸 하나 = 공유 한 번: 사진 파일 + **마지막에** `item.json`. `item.json` 이 있는 칸만 앱이 가져간다.
- 앱은 **노트를 만든 뒤에만** 칸을 지운다. 실패하면 다음에 다시 — 자료 유실이 없다.
- 노트 글은 Core 가 짠다 (`IncomingShare.note` — 제목은 `FrontMatterParser.firstLine`, 링크는 `NoteLinking.markdownLink`). 확장은 Core 를 쓰지 않는다 — 작고 가볍게.
- 둘러보기 자료(가짜 폴더)에는 넣지 않는다 — 진짜 폴더를 고를 때까지 상자에 둔다.

## ADR-0001 과의 관계

상자는 **앱 DB 가 아니다.** 잠깐 맡아 두는 곳이고, 노트가 된 칸은 남지 않는다. 노트의 원본은 여전히 사용자 폴더의 `.md` 다.

## 대가

- 받은 글은 **앱을 열어야** 노트가 된다 (확장에서 바로 폴더에 생기지 않는다). 사용자 확인: 앱을 켜 둔 채 공유하고 돌아오면 바로 들어온다 (빌드 81 · 6번).
- 앱 그룹이 개발자 콘솔 등록에 묶인다 — 새 번들 ID · 그룹을 바꾸면 콘솔도 바꿔야 한다. 배포 흐름(`testflight.yml`)이 확장 · 앱 그룹 자격 · 판 번호를 올리기 전에 본다.

## 다시 열 조건

확장에서 사용자 폴더에 직접 쓰는 길이 기기 · 폴더 종류 모두에서 확인되면 (지금은 확인할 칸이 없다).
