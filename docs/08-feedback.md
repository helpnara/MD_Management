# 2주차 — 라이브 편집기 (ADR-0005)

지금 쓰기 화면은 원문을 고정폭으로 보여 주기만 한다. L1 부터 간다.

## L1 을 어떻게 검증했나 (2026-09-13)

**한 문단 → 한 `ParagraphStyle`** 을 내는 순수 함수 `LineStyler` 를 Core 에 두고,
기댓값은 `Tools/golden` 이 `markdown-it-py` 로 따로 계산한다 (사례 44건).

**테스트가 견주는 것은 오프셋 숫자가 아니라 오프셋으로 잘라 낸 글자다.** 한 칸만
틀려도 잘린 글자가 달라지므로, 숫자를 눈으로 맞춰 보는 것보다 훨씬 촘촘하다.
이모지가 낀 줄(`🙂 **굵게** 다`)이 사례에 있는 이유다 — UTF-16 에서 이모지는 두 칸이다.

**이 칸이 실제로 잡은 것:**

| 잡힌 것 | 어디서 |
|---|---|
| `String.Index(utf16Offset:in:)` 은 옵셔널이 아니다 | CI 리눅스 빌드, 1분 |
| `***글***` 은 emphasis 가 strong 을 **감싼다** (같은 자리에 겹치는 게 아니다) | 파이썬 대조를 쓰기 전, 토큰을 찍어 보다가 |
| `_` 는 낱말 안에서 강조가 아니다 (`snake_case_name`) | 같은 자리 |

셋 다 **손으로 기댓값을 적었으면 그대로 통과했을** 것들이다.

### `파일` 앱에서 `.md` 를 눌러 열기 (사용자 요청, 2026-09-13)

**iOS 에는 확장자마다 기본 앱을 정하는 설정이 없다.** `설정 → 앱 → 기본 앱` 은
브라우저 · 메일 · 메시지 같은 것만 다루고 문서 종류는 목록에 없다. 앱이 스스로를
`.md` 의 기본 앱으로 만드는 API 도 없다. **그래서 켜고 끄는 스위치를 만들 수 없다** —
없는 스위치를 그려 두면 눌러도 아무 일이 없어 더 나쁘다.

할 수 있는 것과 한 것:

| 무엇 | 어떻게 |
|---|---|
| `파일` 앱의 **공유 · 다음으로 열기** 목록에 뜨기 | `UTImportedTypeDeclarations` + `CFBundleDocumentTypes` (`net.daringfireball.markdown`, `LSHandlerRank: Owner`) |
| 내 폴더 **안**의 파일을 누르면 | 그 노트를 **바로 연다** (`Paths.relative(of:under:)` 로 가린다) |
| 폴더 **밖**의 파일을 누르면 | 가져올지 묻고, 가져오면 **복사본**을 만든다. 원본은 안 건드린다 |
| 설정 화면 | 어디를 눌러야 하는지 적어 둔다. 스위치 대신 **길 안내**다 |

**밖의 파일을 그 자리에서 고치게 하지 않는다.** 보안 범위 접근이 언제 끊길지 모르는
파일에 자동 저장을 걸면 저장이 조용히 실패한다 — 이 앱에서 가장 피하고 싶은 일이다.

`Paths.relative(of:under:)` 는 **글자 앞부분만 견주면 안 된다.** `/a/bc` 는 `/a/b` 안이
아닌데 앞부분은 같다. 조각 단위로 견주고, 한글이 NFD 로 와도 되게 NFC 로 맞춘다 (A13).

### 아직 안 된 것 (다음 빌드)

| 무엇 | 언제 |
|---|---|
| 인용의 **회색 세로선** | L3 — TextKit 2 프래그먼트가 필요하다. 지금은 들여쓰기 + 옅은 글자색 |
| **머리말(`---` … `---`)을 통째로 흐리게** | 지금은 `---` 만 수평선으로 흐려지고 `title:` 줄은 본문처럼 보인다 (빌드 7 스크린샷). 문단 하나만 보는 `LineStyler` 로는 못 하고, 문서 첫머리라는 문맥이 필요하다 |
| 마커 **숨기기** (커서가 없는 문단) | L2 |
| 사진 · 체크박스를 **그 자리에 그리기** | L3 |
| 밖에서 파일이 바뀐 걸 알아채기 (충돌) | L2 뒤 |
| 새 노트 만들기 · 이름 바꾸기 · 지우기 | 3주차 |

## 스크린샷 심판이 늑대를 불렀다 (2026-09-13, 빌드 7)

빌드 7 의 스크린샷 단계가 **20분 넘게 같은 화면을 다시 찍었다.**

| 파일 | 크기 | 판정 |
|---|---|---|
| `ipad/01-split.png` | 203,852 → 203,852 → **312,271** | 처음 둘은 **정말 덜 그려졌다.** 가드가 제 일을 했다 |
| `ipad/03-large-text.png` | 239,561 → 239,561 → 239,561 | **다 그려진 화면이다.** 가드가 헛짚었다 |

**문턱값(아이패드 250,000)을 낮추는 것으로는 못 고친다.** 같은 실행에서 덜 그려진
화면이 203,852 이고 다 그려진 큰 글씨가 239,561 이라 **숫자 하나로는 안 갈린다.**
큰 글씨는 글자가 크고 수가 적어 PNG 가 작아지는데, 나는 빌드 4 에서 보통 글씨
화면(307KB)만 보고 문턱을 정했다.

**갈리는 것은 크기가 아니라 "멎었는가" 다.** 덜 그려진 화면은 찍을 때마다 크기가
달라진다. 바이트까지 똑같이 두 번 나오면 화면이 멎은 것이고, 그러면 작은 것은 시간
탓이 아니라 **내용 탓**이다. 그 규칙을 `shoot()` 에 넣었다 — 진짜 빈 화면은 여전히
`SHOOT_FLOOR`(60,000) 아래라 걸린다.

**교훈.** 심판이 헛짚으면 그 심판을 믿지 않게 된다. 빌드 4 의 교훈("스크린샷 심판은
믿을 만하게 만들어야 심판이다")의 뒷면이다 — 그때는 **놓치는 것**을 고쳤고, 이번에는
**헛짚는 것**을 고쳤다. 둘 다 심판을 못 쓰게 만든다.

곁들여 알게 된 것: **아이패드 시뮬레이터 첫 부팅이 2분 36초** 걸린다 (`Data
Migration`). 빌드 시간을 볼 때 이것을 빼고 봐야 한다.

## 빌드 7 스크린샷 — **편집기가 빈 화면이었다** (2026-09-13)

빌드는 초록이었고 가드도 통과했는데, 스크린샷을 눈으로 보니 **편집기 칸에 글이
하나도 없었다.** 제목 · 배너 · 툴바는 다 있었다. 아이폰 · 아이폰 큰 글씨 ·
다크 · 아이패드 상세 칸 **넷 다** 비어 있었다.

### 왜 못 잡았나

| 화면 | 크기 | 가드 판정 |
|---|---|---|
| `02-note.png` (빈 편집기) | 114,161 | 문턱 100,000 을 넘어 **통과** |

**파일 크기로는 "안이 비었는가" 를 못 잰다.** 내비게이션 바 · 상태 띠가 늘 뭔가를
그리기 때문에 빈 편집기도 100KB 를 넘는다. 같은 대리 지표가 이제 세 번 틀렸다
(빌드 4 놓침 · 빌드 7 헛짚음 · 빌드 7 놓침).

그래서 **화소를 직접 센다** — `Tools/ci/not-blank.py`. 내용 칸을 잘라 바탕색과
다른 화소의 비율을 본다. 볼 곳은 화면마다 다르므로 비율로 적어 준다 (아이패드는
오른쪽 칸이 본문이다 — 왼쪽 둘은 사이드바와 목록이라 편집기가 비어도 글자가 있다).

실제 값으로 갈린다: **되는 화면 3.5~12%, 빈 편집기 0.00%.**

**이 심판은 그것이 놓친 바로 그 스크린샷으로 시험했다** — 여기 리눅스에 Pillow 가
있어서 가능했다.

### 무엇이 원인이었나

두 가지를 한꺼번에 고쳤다.

**(1) 글이 화면보다 늦게 온다.** 노트를 고르면 화면이 먼저 그려지고 파일은 그 뒤에
읽힌다. 그 사이 편집기는 **빈 문자열로 한 번 그려진다.** 그런데 `updateUIView` 가
"같은 노트면 건너뛴다" 로만 판단해서, 뒤늦게 온 글을 영영 안 넣었다.

이제 노트 이름뿐 아니라 **글이 바뀌었는가 · 사용자가 손댔는가**까지 본다. 손댄
뒤라면 그것이 최신이므로 덮지 않는다 — 덮으면 자료가 사라진다.

**(2) TextKit 2 를 손으로 조립했다.** `NSTextContentStorage` + `NSTextLayoutManager`
+ 커스텀 `NSTextStorage` 를 직접 엮었는데, 이것은 **여기서 컴파일해 볼 수 없는
조립**이라 위험이 컸다. 틀려도 오류가 안 나고 빈 화면만 뜬다.

`UITextView(usingTextLayoutManager:)` 가 만들어 주는 TextKit 2 를 쓰고, 칠하는
일은 `NSTextStorageDelegate` 로 붙였다. `didProcessEditing` 은 **속성을 바꾸라고
애플이 정해 둔 자리**라 되돌리기 규칙(ADR-0005)도 그대로 지킨다. 커스텀
`NSTextStorage` 서브클래스가 통째로 없어졌다 — required 생성자 문제도 같이 사라졌다.

**교훈.** 원격 세션에서 **컴파일도 실행도 못 해 보는 조립**은 그 자체로 위험이다.
프레임워크가 만들어 주는 것을 쓰고 갈고리만 거는 쪽이, 같은 일을 하면서 틀릴 자리가
훨씬 적다.
