# 빌드 114 — 1.1.11 · 259 오래 걸리는 일에 진행 표시

> 2026-10-20 사용자 (빌드 113 *0-6번 확인 완료* 뒤) — *규모 시험을 하면서 찾은 것인데 지우거나 로딩하거나 등등 작업 시간이 오래 걸리는 경우 화면이 멈춰있는 것처럼
> 보이는데 이 부분에 진행률을 표시해줘서 사용자가 진행 중임을 인지할 수 있게 화면을 개선하자. 전수 조사해서 필요하다고 생각되는 부분에 모두 기능을 넣어줘.
> 특이사항이 없다면 빌드해서 체크리스트 주고 심사 제출까지 같이 준비하자.*

## 고친 것

**장치 하나 — 화면 아래 띠** (`LibraryModel.working` · `WorkBand` · `WorkMeter`). 오래 걸릴 수 있는 일을 이것으로 감싸면, **0.4초가 지나도 안 끝났을 때만**
띠가 뜬다 (빨리 끝나는 일에 띠가 번쩍이지 않게). 몇 개 중 몇 개인지 알면 **막대 + `n / N`**, 모르면 **도는 표시** (+ 지금까지 한 수). 끝나면 저절로 걷힌다.
안에서 또 부르는 일(폴더 지우기 → 목록 다시 읽기)은 바깥 띠 하나로 간다. 띠는 오류 · 알림보다 먼저 보이고, 설정 시트(아이폰) 안에도 보인다.

**전수 조사 — 감싼 자리 (파일 수 · 노트 수에 비례하는 일)**

| 일 | 띠 | 자리 |
|---|---|---|
| 폴더를 휴지통으로 (폴더 화면 · 규모 시험 지우기) | 막대 — 옮긴 파일 수 | `trashFolder(meter:)` · `finishTrashFolder` · `removeScaleTest` |
| 휴지통 비우기 · 하나 영구 삭제 | 도는 표시 (iCloud 가 지우는 것을 기다린다 — 셀 수 없다) | `finishPurge` |
| 휴지통 열기 (읽기) | 도는 표시 | `reloadTrash` |
| 폴더 이름 바꾸기 · 옮기기 (링크 고치기) | 노트 읽는 수 → 막대 (고친 노트) | `relocateFixingLinks(meter:)` · `attachmentCensus(meter:)` |
| 노트를 휴지통으로 (사진이 든 노트는 폴더 전체를 읽는다) | 도는 표시 | `finishTrash` |
| 노트 옮기기 · 되돌리기 | 도는 표시 | `finishMove` · `restore` |
| 안 쓰는 첨부를 휴지통으로 | 막대 | `trashAttachments(meter:)` |
| 검색 색인 (처음 · 많이 바뀌었을 때) | 막대 — 다시 읽을 노트 수 | `SearchIndex.refresh(meter:)` — 제 띠로 따로 (부른 일보다 오래 갈 수 있다) |
| 폴더를 처음 읽을 때 (앱 켤 때 · 폴더 바꿀 때) | 도는 표시 | `use` |
| 사진 여러 장 · 문서 여러 개 넣기 | 막대 — 장 수 | `insertPhotos` · `attachDocuments` |
| 공유로 받은 것 넣기 | 막대 — 받은 수 | `importShared` |
| 공유할 파일 묶기 (링크한 노트 함께) | 도는 표시 | `share` |
| 규모 시험 노트 만들기 | 막대 (진단의 숫자와 함께) | `makeScaleTest` |

**이미 있던 것은 그대로** — 이미 있는 파일 연결 목록 읽기 · 안 쓰는 첨부 세기 · 받는 중인 노트 · 진단의 색인 다시 만들기는 제 화면에 도는 표시가 있다.
**넣지 않은 것** — 노트 열기 · 저장 · 검색 · 목록 읽기(폴더 하나)는 빌드 112 뒤로 0.1초 안팎이라 띠가 뜰 일이 없다.
