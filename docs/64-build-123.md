## 실기기 시험 방안 — 어떻게 확인하나 (2026-10-25)

> 사용자 — *체크리스트의 실기기테스트를 어떻게 하면 좋을지 고민해서 방안을 수립해줘.*

**어려운 점.** 274 · 275 는 *노트가 수천 개 · 그중 다수가 아직 기기에 없는* 상태에서만 드러난다. 사용자의 금고는 264개 · 모두 받아져 있다.
시뮬레이터에는 iCloud 가 없어 CI 스크린샷으로도 못 본다 (CLAUDE §2 표 — 맨 아래 칸, 사람만 잡는다).

**방안 — 다섯 원칙.**

| # | 원칙 | 이번에 어떻게 |
|---|---|---|
| 1 | **상태를 앱이 만든다** — 새 기기 · 저장 공간 정리를 사람이 흉내 내지 않는다 | 시험 도구의 *노트 3000개 만들기* · *이 기기에서 내리기* · 진단의 *색인 다시 만들기* 세 단추로 **새 기기와 같은 색인**을 만든다 |
| 2 | **초시계를 들지 않는다 — 앱이 잰 값을 읽는다** | 진단의 `마지막 갱신` (초) · `제목만 넣은 노트` · `모두 받기` 단추의 수 · 아래 띠의 *n / N* |
| 3 | **싼 것 → 비싼 것 순서** — 사진 · 데이터가 드는 것은 한 번에 | 매번 보는 것(0~2, 1분) → 규모 시험(3~10, 와이파이 · 충전기 · 약 20분) → 아이패드(선택) |
| 4 | **기다리는 자리를 적는다** | iCloud 가 3,000개(약 20MB)를 다 올려야 내릴 수 있다 — *못 내림 n개* 가 나오면 몇 분 뒤 다시 누르면 된다. 앱이 알려 주므로 사람이 짐작하지 않는다 |
| 5 | **끝에 치운다** — 규모 시험 폴더를 남기지 않는다 | 마지막 번호가 *규모 시험 폴더 지우기 → 휴지통에서 영구 삭제* |

**찾는 낱말을 미리 정해 둔다** (코드에서 읽었다 — `LibraryModel.scaleNote`). 규모 시험 노트의 제목은 `시험 1` ~ `시험 3000`,
본문에는 11번째마다 `노후자금 계획을 다시 봅니다.` 가 들어 있다 → 본문 낱말은 **`노후자금`**, 제목 낱말은 **`시험 2200`**.
(사용자의 노트에도 `노후자금` 이 있을 수 있다 — 그래서 *`시험 …` 노트가 결과에 있나 없나* 로 본다.)

**다음에도 쓰는 것.** 확인 목록은 앞으로도 **매번(1분) · 이번 변경 · 규모 시험(한 번)** 셋으로 나눈다. 규모 시험 칸은
